# 《暖穗鸡舍》VR / 手机陀螺仪农场陪伴游戏产品文档

整理日期：2026-05-16  
项目方向：手机陀螺仪 / 轻 VR / 全景互动 / 治愈系小鸡舍投喂与陪伴小游戏  
参考材料：

> 合规说明：本文中的“星露谷”只作为内部风格参考和讨论语境，不建议作为正式产品名、宣传语或上线素材来源。正式项目应使用原创名称、原创角色、原创鸡舍场景、原创 UI、原创音效和原创世界观，避免直接使用现有游戏 IP 的角色、地名、物品图标、UI、音乐、文案或具体美术资产。

正式推荐名称：**《暖穗鸡舍》**

命名理由：

- “暖”对应晨光、治愈、陪伴感。
- “穗”对应谷物、饲料、农场季节感。
- “鸡舍”保留当前 MVP 的核心识别度。
- 名称可向鸡舍、院子、作物、加工、节庆和 VR 空间自然扩展，不局限于单一投喂玩法。

## 一、项目定位

### 1. 一句话概念

玩家通过手机陀螺仪或 VR 视角进入一个温暖的小鸡舍，在第一人称视角中环顾四周，寻找小鸡、料斗、食槽和鸡蛋，通过“凝视 + 点击 / 手柄射线”完成拿干草、投喂、抚摸和拾取鸡蛋的日常循环。

### 2. 产品核心

这不是一个高强度挑战游戏，而是一个以“空间存在感 + 治愈反馈 + 轻日常循环”为核心的互动小品。

核心体验：

```text
环顾鸡舍
-> 找到可互动对象
-> 对准并点击
-> 小鸡反馈 / 物品变化 / 轻音效
-> 完成今日照料
-> 获得温暖结算
```

### 3. 项目关键词

- 手机陀螺仪
- 伪 VR / 轻 VR
- 360° 虚拟空间
- 治愈小鸡舍
- 第一人称投喂
- 凝视交互
- 空间音频
- 轻养成
- 无压日常
- 短局陪伴

### 4. 目标平台

优先级建议：

1. **H5 手机网页 MVP**
   - 使用陀螺仪控制视角
   - 点击屏幕互动
   - 可加入拖动视角备用方案

2. **抖音小游戏 / 小程序 H5 化版本**
   - 更适合传播和短视频入口
   - 需要确认平台传感器 API 支持情况

3. **WebXR / Three.js 版本**
   - 更像真实 VR / 3D 空间体验
   - 适合作为第二阶段

4. **Unity / Godot VR 版本**
   - 适合正式 VR 设备
   - 不建议作为首个 MVP

## 二、用户与使用场景

### 1. 目标用户

- 喜欢治愈、农场、动物陪伴、轻养成的用户
- 喜欢小鸡、小动物、收集和日常照料的人
- 想在碎片时间里获得轻松反馈的手机用户
- 对 VR / AR / 陀螺仪新鲜交互感兴趣的轻度玩家
- 喜欢“转动手机找东西”的探索型玩家

### 2. 典型场景

#### 场景 A：睡前 1 分钟照料

```text
用户睡前打开小鸡舍，转动手机看一圈，摸摸小鸡、放好干草、捡走鸡蛋。
一局结束后看到“今天的小鸡都吃饱啦”，获得轻微满足感。
```

#### 场景 B：通勤摸一下

```text
用户坐车时打开游戏，不需要大幅转身，只在正前方 ±90° 内环顾。
找到几只小鸡并完成抚摸，像刷一次电子宠物。
```

#### 场景 C：短视频互动传播

```text
视频里玩家转动手机，角落里突然冒出一只躲起来的小鸡。
点击后小鸡冒爱心，镜头有短震和咕咕声，适合做“我的手机里有个小鸡舍”的传播点。
```

## 三、产品愿景与设计原则

### 1. 核心愿景

将“清晨鸡舍日常”转化为第一人称手机陀螺仪 / 轻 VR 体验。

保留温馨、治愈、陪伴感，通过空间视角放大玩家和小鸡之间的亲密互动。

### 2. 设计原则

#### 物理直觉化

玩家看到什么，就应该能自然地理解如何互动。

- 看向料斗：可以拿干草
- 看向食槽：可以放干草
- 看向小鸡：可以抚摸
- 看向鸡蛋：可以拾取

#### 情感正反馈

小鸡的反馈是灵魂。

- 抚摸后冒爱心
- 小鸡开心伸展
- 进食时低头啄食
- 捡蛋时有轻快音效
- 完成照料后有温暖结算

#### 极简 UI

避免大面积遮挡视野的传统面板。

优先使用：

- 中心小准星
- 物品高亮
- 手持物图标
- 小鸡身边浮空状态
- 短文字飘字

#### 坐着也能玩

手机玩家不一定能站起来转 360°。

建议：

- MVP 主要交互范围控制在正前方 ±90°
- 少量隐藏目标可以在侧面
- 提供“重新居中”按钮
- 提供手指拖动视角备用方案

## 四、核心玩法循环

### 1. 标准日常循环

```text
进入鸡舍
-> 校准视角
-> 环顾四周
-> 拿取干草
-> 放入食槽
-> 抚摸每只小鸡
-> 捡拾鸡蛋
-> 查看今日照料结果
-> 明日再来
```

### 2. MVP 单局循环

MVP 不做复杂日期系统，先做一局 60 到 90 秒的照料流程：

```text
开始
-> 找到料斗并拿干草
-> 找到食槽并放干草
-> 抚摸 3 只小鸡
-> 捡 2 个鸡蛋
-> 完成结算
```

### 3. 长线循环

```text
每日照料
-> 小鸡好感度增加
-> 鸡蛋品质提升
-> 解锁更多小鸡品种
-> 解锁鸡舍装饰
-> 收集图鉴 / 相册
```

## 五、核心交互拆解

### 1. 资源获取：拿取干草

目标对象：干草料斗 / 干草箱

交互方式：

- 玩家转动手机或 VR 视角
- 中心准星对准料斗
- 料斗出现轮廓高亮
- 点击屏幕 / 按下扳机

状态变化：

```text
若剩余干草 > 0：
  当前持有物 = 干草
  干草数量 -1
  右下角出现手持干草图标
否则：
  出现提示：干草不够啦
```

反馈：

- 干草沙沙声
- 手持物浮现
- 料斗轻微晃动

### 2. 投喂操作：放置干草

目标对象：喂食槽

前提条件：

- 玩家必须处于“持有干草”状态
- 食槽必须有空位

交互方式：

- 准星对准空食槽
- 食槽高亮
- 点击放置

状态变化：

```text
当前持有物 = none
食槽状态 = filled
小鸡 AI 感知到食物
附近小鸡进入 Eat 状态
```

反馈：

- 干草落下的轻音效
- 食槽上出现干草模型
- 小鸡转头或靠近

### 3. 情感互动：抚摸小鸡

目标对象：

- 鸡舍内自由移动的小鸡

交互方式：

- 玩家用手机朝向追踪小鸡
- 准星对准小鸡
- 点击模拟抚摸

判定建议：

```text
angleBetween(playerLookDirection, chickenDirection) < petAngle
或
raycast 命中小鸡扩大碰撞盒
```

视觉反馈：

- 小鸡播放开心 / 伸展 / 原地蹦跳动画
- 头顶弹出红色爱心粒子
- 爱心带轻微弹跳

音频反馈：

- 清脆咕咕声
- 不同鸡品种可有不同音色

限制逻辑：

- 每只小鸡每日只能获得一次抚摸好感加成
- 再次点击只播放基础叫声，不再加好感

### 4. 收获产出：拾取鸡蛋

目标对象：

- 地板上的鸡蛋
- 角落草堆旁的鸡蛋
- 后续可加入稀有蛋

交互方式：

- 准星对准鸡蛋
- 点击拾取

反馈：

- 鸡蛋从地面弹起
- 飞向屏幕下方或背包图标
- 出现短提示：`+1 鸡蛋`
- 播放清脆拾取声

品质表现：

- 普通鸡蛋：基础模型
- 银星鸡蛋：银色闪光
- 金星鸡蛋：金色闪光
- 稀有鸡蛋：紫色或彩色粒子

## 六、输入输出系统

### 1. 输入

#### 姿态输入

使用手机传感器：

- `alpha`：水平旋转
- `beta`：俯仰
- `gamma`：倾斜
- gyroscope：角速度

映射：

```text
手机向左转 -> 鸡舍视角向左
手机向右转 -> 鸡舍视角向右
手机上抬 -> 看向高处横梁 / 窗户
手机下压 -> 看向地板 / 鸡蛋
```

#### 触摸输入

- 单击：互动
- 长按：查看小鸡状态
- 双击：重新居中，可选
- 拖动：无陀螺仪备用视角控制

#### VR 输入，可选

- 头显朝向控制视角
- 手柄射线选择目标
- 扳机键互动
- 抓取动作拿干草

### 2. 输出

#### 视觉输出

- 360° 鸡舍场景
- 中心准星
- 可交互对象高亮
- 手持干草图标
- 小鸡爱心粒子
- 鸡蛋拾取飞行动画
- 今日完成结算

#### 音频输出

- 小鸡位置性叫声
- 干草沙沙声
- 鸡蛋拾取声
- 小鸡开心叫声
- 鸡舍环境音
- 木板脚步声

#### 触觉输出

- 对准对象：轻震，可选
- 成功互动：短震
- 完成今日任务：柔和长震

## 七、坐标与交互判定

### 1. 推荐 MVP：360° 球面空间

玩家位置固定在鸡舍中央或门口。

所有对象以方向角记录：

```js
object = {
  id: "chicken_01",
  type: "chicken",
  yaw: 35,
  pitch: -8,
  distance: 2.2,
  interactAngle: 10,
  state: "wander"
}
```

玩家视线：

```js
playerLook = {
  yaw,
  pitch
}
```

互动判定：

```text
如果玩家当前视线与对象方向夹角 < 对象可交互角度：
  对象进入 hover 状态
  准星变成对应 icon
  点击后触发交互
```

### 2. 进阶版本：3D Raycasting

如果使用 Three.js / WebXR：

```text
从摄像机中心发射射线
-> 检测命中的 3D 物体
-> 根据物体 type 执行交互
```

小鸡碰撞盒建议：

- 比模型实际体积大 20%-30%
- 避免手机陀螺仪瞄准太难
- 移动时碰撞盒跟随小鸡中心

### 3. 校准逻辑

玩家点击“开始照料”时：

```text
当前手机朝向 = 鸡舍正前方 0°
```

需要提供：

- 开始时自动校准
- 游戏中“重新居中”按钮
- 传感器不可用时的拖动视角

## 八、状态机设计

### 1. 游戏整体状态机

```text
BOOT
-> PERMISSION
-> CALIBRATE
-> MENU
-> PLAYING
-> RESULT
-> NEXT_DAY
```

### 2. 玩家持有物状态

```text
EMPTY
-> HOLDING_HAY
-> EMPTY
```

### 3. 小鸡 AI 状态机

```text
IDLE
-> WANDER
-> PECK
-> EAT
-> HAPPY
-> SLEEP
```

状态说明：

| 状态 | 行为 |
| --- | --- |
| IDLE | 原地站立，偶尔转头 |
| WANDER | 在鸡舍安全区域随机走动 |
| PECK | 低头啄地 |
| EAT | 走向食槽并进食 |
| HAPPY | 被抚摸后伸展、蹦跳、冒爱心 |
| SLEEP | 后续夜晚或结算状态 |

### 4. 小鸡日常状态

```text
Fed / Hungry
Petted / NotPetted
EggProduced / NoEgg
```

## 九、数值与养成模型

### 1. MVP 数值

| 项目 | 建议值 |
| --- | --- |
| 单局时长 | 60-90 秒 |
| 小鸡数量 | 3 只 |
| 干草数量 | 3 份 |
| 食槽空位 | 3 个 |
| 鸡蛋数量 | 2 个 |
| 每只鸡每日抚摸次数 | 1 次 |
| 完成目标 | 喂食 + 抚摸 + 捡蛋 |

### 2. 好感度

每只小鸡拥有独立好感度：

```js
friendship = {
  min: 0,
  max: 1000,
  hearts: friendship / 200
}
```

行为增减：

| 行为 | 数值 |
| --- | --- |
| 抚摸 | +15 / 日 |
| 喂食 | +8 / 日 |
| 忘记喂食 | -20 / 日 |
| 完成全照料 | 额外 +5 |

### 3. 饱食度

```text
如果今日完成喂食：
  明日小鸡状态 = Fed
否则：
  明日小鸡状态 = Hungry
```

表现：

- Fed：移动活跃，叫声轻快，产蛋率高
- Hungry：移动慢，少叫，头顶出现烦恼气泡，产蛋率降低

### 4. 鸡蛋品质

鸡蛋品质受好感度影响：

| 好感度 | 品质 |
| --- | --- |
| 0-199 | 普通鸡蛋 |
| 200-599 | 银星鸡蛋 |
| 600-899 | 金星鸡蛋 |
| 900-1000 | 稀有鸡蛋 / 大鸡蛋概率提升 |

## 十、场景与对象设计

### 1. 鸡舍空间

MVP 只做一个小鸡舍。

空间元素：

- 木板地面
- 左侧干草料斗
- 右侧喂食槽
- 后方小窗户
- 角落草堆
- 地板鸡蛋
- 3 只小鸡

视角范围建议：

- 主要对象集中在正前方 ±90°
- 少量鸡蛋或小鸡放在侧面作为发现感
- 不要求玩家频繁转身 180°

### 2. 可交互对象

| 对象 | 交互 | 状态 |
| --- | --- | --- |
| 干草料斗 | 拿取干草 | available / empty |
| 食槽 | 放置干草 | empty / filled |
| 小鸡 | 抚摸 / 查看状态 | petted / unpetted |
| 鸡蛋 | 拾取 | onGround / collected |
| 鸡舍门 | 后续出门 | locked / open |
| 窗户 | 后续观察天气 | morning / evening |

### 3. 小鸡类型

MVP：

- 白色小鸡
- 棕色小鸡
- 黄色小鸡

后续：

- 黑羽小鸡
- 花斑小鸡
- 稀有蓝色小鸡
- 节日装扮小鸡

## 十一、UI / UX 设计

### 1. 准星

默认：

- 小型半透明圆点

对准对象时：

| 对象 | 准星变化 |
| --- | --- |
| 小鸡 | 手掌 icon |
| 鸡蛋 | 拾取 icon |
| 干草料斗 | 抓取 icon |
| 食槽 | 放置 icon |

### 2. 手持物

当玩家拿到干草：

- 右下角出现“手持干草”

结算内容：

- 今日照料完成度
- 抚摸了几只小鸡
- 放置了几份干草
- 捡到几个鸡蛋
- 好感度提升
- 明日提示

文案示例：

- `今天的小鸡都吃饱啦`
- `鸡舍里暖烘烘的`
- `有一只小鸡还在等你摸摸`
- `明天可能会有更好的鸡蛋`

## 十二、游戏架构与技术栈

### 1. 推荐 MVP 技术栈

优先方案：

```text
HTML5 + JavaScript + Canvas / DOM
DeviceOrientationEvent
Pointer / Touch Events
Web Audio
Vibration API
localStorage
```

适合：

- 快速验证陀螺仪视角
- 凝视 + 点击交互
- 伪 3D / 360° 图层
- 低成本 H5 分享

### 2. 进阶 Web 3D 技术栈

```text
Three.js
DeviceOrientationControls 或自定义姿态控制
Raycaster
GLTF 模型
Web Audio / PositionalAudio
localStorage
```

适合：

- 真实 3D 鸡舍
- 小鸡模型移动
- 射线点击
- 空间音频

注意：

- 需要本地资源管理
- 移动端性能要严格控制
- 模型、贴图、动画都要轻量

### 3. WebXR 技术栈

```text
Three.js / Babylon.js
WebXR
Raycasting
XR controller input
Spatial Audio
```

适合：

- VR 浏览器
- Quest 浏览器
- 简单 WebXR 原型

不建议作为第一版。

### 4. Unity / Godot 技术栈

适合正式 VR / AR App。

Unity：

- XR Interaction Toolkit
- AR Foundation，可选
- OpenXR
- Animator
- NavMesh

Godot：

- Godot XR
- OpenXR
- NavigationRegion3D
- AnimationPlayer

不建议第一阶段使用，除非团队已经有现成 XR 工程经验。

### 5. 模块划分

```text
InputController
  - 陀螺仪读取
  - 触摸输入
  - 备用拖动视角

CameraController
  - 姿态映射
  - 视角校准
  - 平滑滤波

InteractionSystem
  - 凝视检测
  - 射线检测
  - 高亮管理
  - 点击分发

CoopState
  - 干草数量
  - 食槽状态
  - 鸡蛋状态
  - 今日任务

ChickenAI
  - 漫游
  - 进食
  - 抚摸反馈
  - 好感度

Renderer
  - 鸡舍背景
  - 对象绘制 / 3D 渲染
  - 粒子
  - UI

AudioManager
```

```text
• 玩法类型:
{
  gameplay_details:
  这是一款竖屏、第一人称、手机陀螺仪方向识别、治愈系小鸡舍互动小游戏。

  玩家进入一个原创温暖小鸡舍，通过转动手机环顾四周。屏幕中央有一个小准星。玩家需要对准鸡舍里的可互动对象并点击，完成今日照料任务。

  核心对象：
  1. 干草料斗
     - 用于拿取干草。
     - 玩家对准料斗后准星显示“拿干草”。
     - 点击后，如果干草数量大于 0，则进入“手持干草”状态。

  2. 喂食槽
     - 用于放置干草。
     - 玩家必须先持有干草。
     - 对准空食槽后准星显示“放干草”。
     - 点击后食槽从 empty 变为 filled。

  3. 小鸡
     - 场景中有 3 只原创小鸡。
     - 玩家对准小鸡后准星显示“摸摸”。
     - 点击后小鸡冒爱心，播放开心反馈。
     - 每只小鸡每局只获得一次抚摸加成。
     - 再次点击只播放基础叫声，不再冒大爱心。

  4. 鸡蛋
     - 地上有 2 个鸡蛋。
     - 玩家对准鸡蛋后准星显示“拾取”。
     - 点击后鸡蛋消失或飞入背包，任务进度增加。

  核心循环：
  进入鸡舍
  -> 点击开始并校准视角
  -> 转动手机寻找对象
  -> 拿干草
  -> 放入食槽
  -> 抚摸 3 只小鸡
  -> 拾取 2 个鸡蛋
  -> 完成今日照料
  -> 进入结算页

  核心状态机：
  - BOOT：初始化
  - PERMISSION：请求陀螺仪权限
  - MENU：开始界面
  - CALIBRATE：校准当前朝向为正前方
  - PLAYING：照料小鸡舍
  - RESULT：今日结算

  玩家持有物状态：
  - EMPTY：未持有物品
  - HOLDING_HAY：手持干草

  任务目标：
  - 放置干草：3 / 3
  - 抚摸小鸡：3 / 3
  - 拾取鸡蛋：2 / 2

  计分方式：
  第一版不强调传统分数，使用“今日完成度”作为结算指标。
  - 每放置 1 份干草：完成度 +1
  - 每抚摸 1 只小鸡：完成度 +1
  - 每拾取 1 个鸡蛋：完成度 +1
  - 满完成度为 8

  胜利条件：
  - 完成全部 8 个照料任务。
  - 或倒计时结束时完成度达到 6 以上，显示“基本照料完成”。

  失败条件：
  - MVP 不做强失败。
  - 如果 90 秒倒计时结束且完成度低于 6，显示“还有小鸡在等你照料”。
  - 玩家可以直接重开，不惩罚。

  单局时长：
  - 默认 90 秒。
  - 后续可改为无倒计时的自由照料模式。

  反馈要求：
  - 对准对象时出现高亮和准星提示。
  - 成功互动时有短音效。
  - 抚摸小鸡时出现爱心粒子。
  - 鸡蛋拾取时出现“+1 鸡蛋”飘字。
  - 完成今日照料后显示温暖结算文案。

  结算文案示例：
  - 今天的小鸡都吃饱啦
  - 鸡舍里暖烘烘的
  - 有一只小鸡还在等你摸摸
  - 明天可能会有更好的鸡蛋
}

• 核心交互:
{
  interaction_mode:
  - 手机陀螺仪：控制第一人称观察方向。
  - 点击屏幕：触发当前准星指向对象的互动。
  - 拖动屏幕：无陀螺仪或未授权时的备用视角控制。
  - 重新居中按钮：把当前手机朝向设为鸡舍正前方。
  - 长按小鸡：后续可显示小鸡状态浮窗，MVP 可先不做。

  交互规则：
  - 同一时间只允许 hover 一个最近或最优先的可互动对象。
  - 玩家点击时，如果当前有 hover 对象，则执行对象交互。
  - 如果没有 hover 对象，则播放轻微空点反馈。
  - 小鸡和鸡蛋的交互角度要比普通对象更宽，降低手机瞄准难度。
}

产物技术与合规约束（严格遵守）
{
  tech_constraints:
  • 交付形态:
    产物可以为两种形态之一：
    a) 单文件：所有代码和资源内联于一个 index.html；
    b) 多文件结构：index.html 通过相对路径引用本地的 js/, images/, audio/ 等子目录中的资源。

    MVP 推荐优先使用单文件 index.html，便于本地直接打开和快速测试。

  • 纯离线运行:
    整个作品必须完全离线运行，所有资源必须包含在项目目录内。

  • 无网络请求:
    绝对禁止使用任何形式的网络请求 API，包括 fetch, XMLHttpRequest, axios, WebSocket 等。

  • 无外部资源:
    禁止从任何外部 CDN 或服务器加载资源。
    不得引用 Google Fonts、CDN 脚本、远程图片、远程音频、远程配置。
    如需加载配置文件，请直接写入 JS 常量，或使用内联 JSON：
    <script type="application/json">...</script>

  • 无外部跳转:
    绝对禁止使用 <a> 标签、window.location 或任何其他方式跳转到外部链接。

  • 轻量化:
    最终产物打包为 zip 后，总体积必须小于 8MB。
    第一版建议使用 Canvas 绘制简化鸡舍、对象和粒子，尽量不依赖图片资产。

  • 数据存储:
    如果需要存储数据，例如已照料天数、小鸡好感度、鸡蛋总数，推荐使用 localStorage。
    localStorage 不是 MVP 必须项。
    如实现，必须做好 localStorage 不可用时的兜底，不得导致游戏崩溃。

  • UI 适配:
    ◦ 屏幕方向:
      {screen_orientation: 竖屏}

    ◦ 自适应布局:
      内容界面必须能动态、无缝地适配各种尺寸的移动端屏幕，确保在任何主流手机上都能完整显示，不能出现横向滚动条。

    ◦ 逻辑分辨率:
      建议内部逻辑分辨率固定为 360 × 640。

    ◦ 缩放:

    - 必须处理 iOS Safari 的 DeviceOrientationEvent.requestPermission。
    - 权限请求必须由用户点击按钮触发。
    - 如果权限被拒绝，进入拖动视角模式。
    - 如果设备不支持陀螺仪，进入拖动视角模式。

  • 错误处理:
    必须包含 try-catch 块来捕获潜在错误，并在出错时在页面上显示友好的提示文案：
    {error_handling_text: 哎呀，出错了，请重启试试吧~}

    建议：
    - 初始化主函数包裹 try-catch。
    - gameLoop 内对关键更新流程做基础保护。
    - 出错时停止游戏循环，并显示错误提示层。
```
