# 手机陀螺仪方向识别小游戏框架

整理日期：2026-05-16  
方向：手机姿态感知、陀螺仪瞄准、360°虚拟空间、轻量 AR / 伪 AR 小游戏  
目标：为后续团队讨论、原型立项和玩法验证提供底层逻辑框架

---

## 一、概念定义

这类游戏可以定义为：

**手机姿态感知型 360° / 空间定向小游戏**

玩家不是通过摇杆移动，而是通过“转动手机 / 改变手机朝向”来寻找、瞄准、识别或追踪虚拟目标。

它介于：

- 传统手机小游戏
- AR 扫描小游戏
- 陀螺仪瞄准游戏
- 360°全景互动游戏
- 轻量空间感知游戏

之间。

核心不是“手机真的知道你在哪里”，而是：

> 手机知道自己朝向哪里，然后游戏把这个朝向映射到一个虚拟空间中的视角、准星或观察方向。

---

## 二、底层逻辑框架

最基础的框架是：

```text
手机传感器输入
-> 姿态解算
-> 映射到虚拟世界视角
-> 判断玩家当前看向哪里
-> 检测是否对准目标
-> 玩家点击 / 拍击 / 开火 / 确认
-> 命中、发现、失败或进入下一事件
```

更完整一点：

```text
初始化
-> 获取设备方向权限
-> 校准初始朝向
-> 建立虚拟空间坐标
-> 持续读取手机姿态
-> 更新相机视角 / 准星方向
-> 渲染当前视野
-> 玩家执行动作
-> 命中判定 / 识别判定
-> 反馈与计分
```

这里最重要的是区分两件事：

```text
陀螺仪 / 方向传感器：
知道手机“朝向哪里”

摄像头 / AR / 视觉识别：
知道现实画面里“有什么东西”
```

如果只用陀螺仪，可以做“虚拟空间里的寻找和瞄准”。  
如果要识别现实中的桌子、墙、出口、平面、真实物体，就需要 AR / 摄像头 / 图像识别。

## 三、输入系统

这类游戏的输入可以分成 4 层。

### 1. 姿态输入

来自手机传感器：

- `alpha`：水平旋转，类似指南针方向
- `beta`：前后俯仰
- `gamma`：左右倾斜
- gyroscope：角速度
- accelerometer：加速度
- magnetometer：磁力计，辅助方向，但容易受干扰

常用行为：

```text
手机向左转 -> 视角向左
手机向上抬 -> 视角向上
手机向下压 -> 看向地面或低处
手机快速挥动 -> 拍击 / 闪避 / 格挡
```

### 2. 触摸输入

用于确认动作：

- 点击屏幕：开枪、拍打、抓取、确认
- 长按：蓄力、扫描、锁定
- 滑动：切换武器、换道具
- 双击：快速反应动作

### 3. 摄像头输入，可选

如果做 AR：

- 识别平面
- 识别图片 Marker
- 识别现实空间中的物体
- 叠加虚拟目标
- 让玩家在现实环境中寻找东西

### 4. 声音 / 麦克风输入，可选

适合恐怖、逃脱、捉迷藏类：

- 玩家发出声音会吸引敌人
- 喊出关键词开门
- 根据音量触发事件

---

## 四、输出系统

输出不只是画面，还包括反馈。

### 1. 视觉输出

常见形式：

- 第一人称视角
- 360°虚拟场景
- AR 摄像头叠加
- 雷达 / 指示箭头
- 准星
- 目标高亮
- 屏幕边缘方向提示

### 2. 触觉输出

手机震动非常重要：

- 对准目标：轻震
- 命中：短强震
- 被攻击：连续震
- 靠近出口：心跳式震动
- 拍蚊子成功：清脆短震

### 3. 音频输出

声音可以负责引导方向：

- 左耳有蚊子声
- 背后有敌人脚步声
- 出口方向传来风声
- 危险目标发出低频提示

如果做 360° 寻找类游戏，**空间音频很有价值**。

### 4. UI 输出

UI 要少，不能挡视野：

- 中心准星
- 顶部倒计时
- 目标数量
- 简单雷达
- 方向提示
- 当前任务一句话

## 五、核心坐标逻辑

这类游戏通常需要建立一个虚拟球面或空间坐标。

### 方案 A：360° 球面空间

适合：

- 拍蚊子
- 找敌人
- 找出口
- 找异常物
- 恐怖探索

逻辑：

```text
玩家站在球心
目标分布在球面上的不同方向
手机朝向 = 玩家视线方向
如果视线方向接近目标方向，则目标进入屏幕
```

命中判断：

```text
angleBetween(playerLookDirection, targetDirection) < hitAngle
```

例如：

```text
玩家当前看向角度：水平 40°，俯仰 10°
蚊子位置：水平 43°，俯仰 8°
差值很小
-> 玩家点击
-> 命中
```

这个方案不需要真实 AR，开发成本低，适合 H5。

### 方案 B：虚拟房间空间

适合：

- 逃离房间
- 找钥匙
- 找出口
- 密室逃脱
- 恐怖追踪

逻辑：

```text
玩家位置固定或有限移动
手机朝向决定视角
房间里有门、窗、柜子、敌人、道具
玩家看向某物并点击互动
```

可以做成：

- 伪 3D
- 全景图片
- Three.js 低模房间
- 多张 360° 场景图

### 方案 C：AR 现实叠加

适合：

- 现实桌面上出现蚊子
- 墙上出现敌人
- 房间里找虚拟出口
- 扫描海报进入小游戏

逻辑：

```text
摄像头画面作为背景
AR 系统识别平面或 Marker
虚拟目标锚定在现实空间
玩家转动手机寻找目标
```

优点：

- 沉浸感强
- 传播性好

缺点：

- 权限、兼容、追踪稳定性复杂
- 比纯陀螺仪方案更难

## 六、适合的游戏表现形式

### 1. 拍蚊子 / 打飞虫

最适合入门。

核心循环：

```text
听到蚊子声
-> 转手机寻找
-> 蚊子飞入视野
-> 点击 / 快速挥动手机拍打
-> 命中得分
-> 下一只更快
```

优点：

- 一秒懂
- 适合短视频
- 陀螺仪就能做
- 不需要复杂剧情

关键设计：

- 蚊子不要太小
- 目标进入视野时要有声音提示
- 拍击反馈要爽
- 误拍可以扣时间
- 后期加入“假蚊子 / 毒虫 / 大蚊子”

### 2. 手机陀螺仪射击—深海潜艇炮塔

核心循环：

```text
敌人从不同方向出现
-> 玩家转手机瞄准
-> 点击开火
-> 命中 / 未命中
-> 敌人攻击或逃走
```

适合表现：

- 太空炮塔
- 防空炮
- 僵尸围攻
- 海盗船炮台
- 办公室防御小怪
- 深海潜艇炮塔

关键设计：

- 玩家最好固定站位
- 敌人从四周出现
- 不要让玩家频繁转 360°，会累
- 使用屏幕边缘箭头提示敌人方向
- 命中角度要宽一点，避免挫败

### 3. 逃离某个地方 / 找出口——船舱逃生

核心循环：

```text
玩家被困在一个空间
-> 转动手机观察四周
-> 寻找线索、门、光源或出口
-> 点击调查
-> 解锁下一方向或下一房间
```

适合表现：

- 密室逃脱
- 恐怖走廊
- 船舱逃生
- 地铁站找出口
- 海底基地逃离
- 办公室加班逃离

关键设计：

- 不要一开始做自由移动
- 玩家固定在几个观察点
- 每个观察点是一个 360° 场景
- 找到关键物后切换场景
- 声音和震动引导方向

### 4. 360° 找不同 / 找异常

核心循环：

```text
观察一个全景空间
-> 转手机寻找不合理之处
-> 点击异常
-> 找齐进入下一关
```

适合：

- 恐怖异常
- 办公室怪谈
- 海底异常扫描
- 博物馆找文物
- 校园找线索

优点：

- 关卡成本比 3D 自由游戏低
- 很适合短视频互动
- 可以用 AI 生成场景图或异常物

### 5. 空间雷达 / 寻宝

核心循环：

```text
手机震动或声音提示附近有宝物
-> 玩家转动手机寻找方向
-> 对准后长按扫描
-> 找到宝箱 / 信号 / 生物
```

适合：

- AR 寻宝
- 海底声呐
- 幽灵探测
- 外星信号
- 城市探索

## 七、适合的技术路线

### 轻量 H5 方案

适合快速 MVP。

使用：

- HTML5 Canvas
- DeviceOrientationEvent
- Touch input
- Web Audio
- Vibration API

能做：

- 拍蚊子
- 陀螺仪射击
- 360° 找物
- 简单逃脱
- 全景互动

优点：

- 开发快
- 不用安装
- 适合分享

缺点：

- iOS 权限麻烦
- 传感器精度不稳定
- 不是真实 AR

### WebXR / Three.js 方案

适合更空间化的版本。

能做：

- 3D 房间
- 空间找物
- 简单 VR / AR
- 低模射击

优点：

- 空间感更强
- 可扩展到 VR / AR

缺点：

- 兼容复杂
- 开发成本更高

### Unity / Godot 方案

适合正式 App 或 VR / AR 设备。

能做：

- 真正 AR
- 正式 VR 游戏
- 空间定位
- 手柄 / 手势
- 高质量 3D

缺点：

- 不适合一开始快速验证
- 安装包、审核、设备测试成本高

## 八、最小可行框架 MVP

如果团队要最快验证，我建议先做这个：

### MVP 名称

`360° 拍蚊子`

### 输入

- 手机陀螺仪控制视角
- 点击屏幕拍打
- 可选快速挥动手机作为拍打动作

### 输出

- 蚊子声提示方向
- 目标进入视野
- 中心拍击区域
- 命中震动
- 得分飘字
- 30 秒倒计时

### 核心状态

```text
MENU
-> CALIBRATE
-> PLAYING
-> HIT_FEEDBACK
-> RESULT
```

### 核心数据

```js
playerLook = {
  yaw,
  pitch
}

target = {
  yaw,
  pitch,
  distance,
  size,
  speed,
  score,
  active
}

hitRule = {
  maxAngle: 8,
  tapWindow: 0.15
}
```

### 命中逻辑

```text
玩家点击时：
计算玩家当前朝向和蚊子方向的夹角
如果夹角小于命中阈值：
  命中
否则：
  拍空
```

### 关卡节奏

```text
第 1-10 秒：蚊子慢，提示明显
第 10-20 秒：蚊子变快，出现多个方向干扰
第 20-30 秒：出现高分大蚊子或假目标
```

## 九、设计注意点

### 1. 一定要有校准

玩家点击开始时，把当前手机朝向设为正前方。

```text
当前朝向 = 游戏世界 0°
```

否则不同玩家打开游戏时方向会乱。

### 2. 不要要求玩家大幅转身

手机小游戏里，玩家可能坐着、站着、在地铁上。

建议：

- 主要目标出现在正前方 ±90°
- 少量目标出现在侧后方
- 不要频繁要求 180° 转身
- 可以用“重新居中”按钮

### 3. 命中判定要宽

陀螺仪抖动、延迟、手持误差都会影响体验。

建议：

```text
拍蚊子：命中角 8° 到 15°
射击：命中角 4° 到 8°
找出口：识别角 10° 到 20°
```

### 4. 必须处理传感器权限

尤其 iOS Safari：

- 需要用户手势触发权限申请
- 不能页面一打开就读陀螺仪
- 如果权限被拒绝，要提供触摸备用操作

### 5. 要提供无陀螺仪备用方案

例如：

- 拖动画面转视角
- 滑动瞄准
- 点击方向按钮

否则部分设备无法玩。

## 十、建议优先做的三个方向

### 第一优先：360° 拍蚊子

原因：

- 最容易验证
- 输入输出最清楚
- 短视频传播强
- 失败成本低
- 不需要复杂世界观

### 第二优先：陀螺仪炮塔射击

原因：

- 比拍蚊子更像游戏
- 可扩展关卡、武器、敌人
- 适合做分数挑战

### 第三优先：空间逃脱 / 找出口

原因：

- 更有内容感
- 适合做恐怖、悬疑、解谜
- 但关卡设计成本更高

---

## 十一、需要继续确认的问题

1. 团队想做的是 **纯陀螺仪虚拟空间**，还是 **打开摄像头的 AR**？
2. 目标平台是 **H5 网页**、**抖音小游戏**，还是 **原生 App / Unity**？
3. 玩家是否需要真的转身 360°，还是只在正前方小范围转手机？
4. 游戏更偏 **爽快反应**，还是 **探索解谜**？
5. 是否接受“无陀螺仪时用手指拖动画面”的备用操作？

---

## 十二、当前建议

我个人建议：先不要做真 AR，先做一个 **H5 陀螺仪 360° 拍蚊子 MVP**。

原因：

- 最能验证这类玩法是否成立
- 技术风险最低
- 可以快速测试陀螺仪手感、命中判定、校准和备用操作
- 如果这个 MVP 不好玩，后续做 AR / 3D / 逃脱都会变得更难

推荐验证目标：

```text
玩家是否能在 5 秒内理解玩法？
转手机寻找目标是否有趣？
点击命中反馈是否爽？
陀螺仪是否稳定？
坐着玩是否舒服？
失败后是否愿意再来一局？
```
